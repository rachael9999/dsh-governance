**说明**：本清单基于 PE Ontology 的 relations 构建深度推理链条，每个问题都不是孤立的，而是处于因果链、影响链或验证链中。通过追踪 metric 之间的关联关系，揭示表面数据背后的深层风险。

**Ontology 版本**: nalinwei-instance v1.0
**Metrics 总数**: 569
**Risk Rules 总数**: 38
**Relations 总数**: 622

**问题设计理念**:
- ❌ **浅层问题**: '这个 metric 是多少？' → 只问数值
- ✅ **深层问题**: '这个 metric 为什么是这个值？它受什么影响？它会影响什么？它与其他 metric 的关系是否合理？' → 问因果、问链条、问一致性

## 使用方法

### 1. 按链条追踪

每个链条都是一个完整的推理逻辑，建议按顺序核验：
1. 从根 metric 开始，向上游追溯影响因素
2. 向下游追踪影响结果
3. 检查验证链条中各 metric 的一致性
4. 评估风险级联是否可能触发

### 2. 识别不一致

深层问题的核心价值是识别 metric 之间的**不一致**：
- **因果不一致**: 因变果不变（如管理层流失但人均效率上升）
- **趋势不一致**: 两个应正相关的 metric 背离（如收入增长但现金流恶化）
- **逻辑不一致**: 推导链条断裂（如产能利用率高但达成率低）

### 3. 自动化核验

每个问题关联的 metrics 和 risk rules 可通过 semantic runtime 自动核验：
```bash
# 示例：核验链条 1 的所有 metrics
dsh ontology get --metrics CORP.016,CORP.023,CORP.024,CORP.027,CORP.030
dsh ontology check-rules --rules RR.MGMT.011.001
```
